## Steps (each lands as its own MR on a feature branch)

Ordered so the riskiest unknown retires first. Each step: write the failing test first (RED), make it pass with minimum code (GREEN), refactor under the passing test. Cite the pinned Oracle (`v0.82.0`, ADR 0007) with a permalink for any behavior with a pi equivalent; state explicitly where there is no pi equivalent (PHILOSOPHY §9.5).

### Step 1 — Crate skeleton + panic-safe terminal restore + cargo-deny guard

- Create `crates/pi-render` per ADR 0026. Workspace `Cargo.toml` gains `pi-render = { path = "crates/pi-render" }`. Add ratatui + crossterm only (later steps add their specific deps incrementally, all workspace-unified from the first addition).
- Terminal backend: enter/leave alt screen, raw mode, mouse capture. **Single owned restore path installed as a panic hook before first draw** (P15, P3). Zero-size terminal guard in the resize handler (P15).
- **SIGTSTP/SIGCONT suspend/resume handling** (P14, ADR 0024): install signal handlers mirroring Codex-RS's `SuspendContext` [[7]](https://github.com/openai/codex/blob/31519549/codex-rs/tui/src/tui/job_control.rs). On SIGTSTP: `PopKeyboardEnhancementFlags` + leave alt screen + disable raw mode + `libc::kill(0, SIGTSTP)`. On SIGCONT: re-enter alt screen + enable raw mode + `PushKeyboardEnhancementFlags`. crossterm exposes the full push/pop pair [[4]](https://github.com/crossterm-rs/crossterm/blob/master/src/event.rs); it has no built-in signal handling (issue #494 open) [[6]](https://github.com/crossterm-rs/crossterm/issues/494), so the app installs handlers itself.
- **`cargo deny` guard lands here** (P16, ADR 0024 "starts here"): create `deny.toml` with `[bans] multiple-versions = "deny"` [[8]](https://embarkstudios.github.io/cargo-deny/checks/bans/cfg.html) scoped to crossterm/terminal-backend, and add the `EmbarkStudios/cargo-deny-action` CI job [[9]](https://github.com/EmbarkStudios/cargo-deny-action) in this step so Steps 1-7 run under the guard.
- Failing test first: assert terminal state is restored after a panic, after normal exit, after a zero-size resize, and after a SIGTSTP/SIGCONT cycle (pty harness: spawn process, send SIGTSTP, probe terminal state, send SIGCONT, assert clean). Tests need a pty harness (the existing supervisor chaos test already uses process spawning — `crates/pi-core/tests/supervisor_integration.rs`).
- **No pi equivalent** (pi is single-process JS; render thread, terminal backend, signal handling are pi-rs-native, ADR 0013). State explicitly per §9.5.
- `pi-core` depends on `pi-render` (one-way). `mock-host` binary stays render-free. README mermaid diagram already updated this session (ADR 0026); re-confirm in the Step 1 PR.

### Step 2 — Render thread + tokio split + channel contract

- Dedicated OS threads: the render thread blocks on `recv_timeout(16ms)` on a unified `std::sync::mpsc` channel (ADR 0030), drains `RenderEvent`s, projects (Step 3), `terminal.flush()` wrapped in mode 2026 [[5]](https://docs.rs/ratatui/latest/ratatui/backend/struct.CrosstermBackend.html), writes. Never awaits (ADR 0013, ADR 0024). A separate input reader thread reads input and sends `InputEvent`s over the same channel, so the render thread wakes immediately for both input and render events (ADR 0030 supersedes ADR 0013's input-on-render-thread clause). The ≥16ms coalescing budget is ADR 0010's.
- `RenderEvent` contract mirrors pi's two-layer streaming model (ADR 0029): the 10 agent-loop variants of pi's `AgentEvent` [[28]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/agent/src/types.ts#L422-L437) with `MessageUpdate` nesting pi's 12-variant `AssistantMessageEvent` [[29]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/ai/src/types.ts#L491-L503) (the nesting mirrors pi's `message_update.assistantMessageEvent` [[30]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/agent/src/types.ts#L432)), plus four pi-rs-native render controls (`Resize`, `ThemeChanged`, `FrameBufferUpdated`, `Quit`). **Typed payloads** (ADR 0029): messages and content blocks are typed Rust types (`MessageRef` per-role enum mirroring the `Message` union, `ContentBlock` enum mirroring the content union), not `serde_json::Value`. The agent loop (Phase 3) sends typed structs with zero serialization via `RenderHandle::send` (sync non-blocking `try_send`, safe to call from tokio tasks, ADR 0030); `pi-replay` (Step 7) parses `Value`→typed at the replay boundary. `Value` is used only for `ToolCall::arguments` and tool-execution `result`/`partial_result` (arbitrary model/tool data the renderer displays but never interprets). The per-delta `partial` snapshot pi carries is omitted (redundant under ADR 0013); the `message` field on `MessageUpdate` is kept as the mid-stream metadata channel (usage/stop_reason/diagnostics change during the stream). `std::sync::mpsc` channel (ADR 0030; not tokio mpsc, because the render thread is synchronous and needs `recv_timeout`). Single-threaded mutation of the RMM, no locks (ADR 0013). Backpressure on a full channel is the caller's concern (Phase 3).
- Input read on a dedicated reader thread (ADR 0030; supersedes ADR 0013's input-on-render-thread clause). Focus routing is **Phase 3** (ROADMAP Phase 3 deliverable: "ctx.ui frame buffers and focus routing, ADR 0003"); Phase 2 has no extension UI so focus is trivially always-transcript, no stub built (YAGNI, PHILOSOPHY §5).
- Failing test: assert a `RenderEvent` sent from any thread (sync `RenderHandle::send`) is applied before the next frame; assert the render thread never blocks on the channel (non-blocking drain).
- **Parity**: the agent-loop and streaming variants mirror pi's `AgentEvent`/`AssistantMessageEvent` at v0.82.0 (ADR 0029, permalinks L422-L437 / L491-L503). The render-thread/tokio split and the input reader thread are pi-rs-native (pi is single-process JS, ADRs 0013/0030). State explicitly per §9.5.

### Step 3 — Retained Message Model + cell grid + cell diff + mode 2026 + frame-buffer compositing

- The RMM the render thread owns (ADR 0004, ADR 0031). **Visible-window rendering** (ADR 0031): the RMM holds the message list (`Vec<MessageRef>`) + `scroll_offset`; the projection renders only `scroll_offset..scroll_offset+viewport_height` into ratatui's terminal-sized `Buffer`. O(viewport_height) per frame, not O(total_lines). ratatui has no scrollback/virtualization; the RMM owns scroll state (ADR 0004). **Pin-to-tail auto-scroll** in Phase 2: `scroll_offset = max(0, total_rendered_lines - viewport_height)`. Interactive scrollback, search, copy-mode are **Phase 3** (P6; ADR 0007 says copy-mode surfaces during dogfood). Selection/copy-mode is Phase 3 (alt screen + mouse capture eats native selection, ADR 0004).
- **Message-granular line cache** (ADR 0031): finalized messages cache rendered lines keyed by `(content, width, theme)`, like pi's `Markdown.cachedLines` (markdown.ts L152-L157). Invalidated on resize (width changed) or theme change. The streaming tail message is never cached. Step 5 formalizes as block-granular (ADR 0010).
- ratatui `Buffer` + `Buffer::diff` (ADR 0024) [[1]](https://docs.rs/ratatui/latest/ratatui/prelude/buffer/struct.Buffer.html). `Terminal::try_draw` does `Buffer::diff` + `Backend::draw` + `Backend::flush` internally; we do not call `Buffer::diff` ourselves. The real `FrameSink` impl owns a `Terminal<SyncBackend>` and calls `try_draw(|frame| project(state, frame))` (ADR 0031). Step 2's `CountingSink` stays for tests.
- **SyncBackend wrapper** for mode 2026 (ADR 0024, ADR 0031): a custom `Backend` wrapping `CrosstermBackend` that injects `BeginSynchronizedUpdate` before `backend.draw()` and `EndSynchronizedUpdate` after. This is the tightest BSU/ESU pair (P12). Mode 2026 capability queried at startup (`CSI ? 2026 $ p`), graceful degrade where unsupported (cell-diff minimizes tearing, P12). pi uses BSU/ESU (tui.ts L1329/L1349).
- Real crossterm `InputSource` impl for the reader thread (ADR 0030) lands here too (Step 2 uses `NullInput`).
- **Frame-buffer compositing path** (ADR 0003, ADR 0031): the projection composites a frame-buffer region from `RenderEvent::FrameBufferUpdated` into the visible window: frame buffer lines written into the ratatui `Buffer` at the region coordinates. Source is **synthetic** in Phase 2 (a test fixture, not the Host Protocol. ROADMAP Phase 2: "host frame buffers may be faked"). Focus routing stays Phase 3.
- **Tests are ASCII-scoped** (width is trivial in ASCII): ratatui's `Buffer` uses `unicode-width` (the P13 failure class, verified) [[2]](https://github.com/ratatui/ratatui/blob/1ce29d66/ratatui-core/src/buffer/cell_width.rs) before Step 4 introduces the projection-layer width. Step 4 introduces the grapheme corpus that exposes the `unicode-width` limitation and replaces it.
- **Resize** (ADR 0031): invalidate the line cache (width changed, cached lines are wrong), re-render the visible window at the new width. ratatui's `autoresize` handles `Buffer` dimensions. Required for correctness (P5).
- Failing test: assert a single-cell change produces a single-cell diff (P9); assert resize re-wraps without scrollback corruption (P5); assert mode 2026 degrade path runs without malformed output (cell-diff minimizes tearing but does not guarantee zero tearing on unsupported terminals, P12); assert a synthetic frame buffer composites into the grid.
- **Pi equivalent**: pi's `doRender` (tui.ts [L1258](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/tui.ts#L1258)) does line-granular differential rendering via `previousLines` with a line-diff loop ([L1378](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/tui.ts#L1378)), BSU/ESU wrapping ([L1329](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/tui.ts#L1329)/[L1349](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/tui.ts#L1349)), and `previousViewportTop` auto-scroll. pi re-renders ALL components every frame (TUI.render walks all children, L280-L289) relying on per-component caching (Markdown.cachedLines, L152-L157). pi-rs's cell-granular diff (via ratatui Buffer::diff) + visible-window rendering is the improvement over pi's line-granular diff + render-all pattern (P9). Cite with line anchors.

### Step 4 — Grapheme-width engine + corpus

- `GraphemeWidth` trait (ADR 0025, ADR 0032). `runefix-core` impl (research.md) [[15]](https://crates.io/crates/runefix-core). **Direct cell writing** (ADR 0032): the projection bypasses `set_string` (which uses `unicode-width` and skips zero-width graphemes) and writes cells directly via `buf.get_mut(x, y)` + `set_symbol` + `set_diff_option(CellDiffOption::ForcedWidth(width))`. For width-2 graphemes, the trailing cell at `(x+1, y)` is reset. This is the only way to use runefix-core's grapheme-aware width with ratatui.
- Wrapping: replace the ASCII-scoped `wrap_text` (char count) with runefix-core's `split_by_width(text, width)` which wraps by display width preserving grapheme boundaries.
- P13 corpus as snapshot tests: single-codepoint emoji, ZWJ family, VS16, CJK (Hiragana/Katakana/Han), East-Asian-ambiguous, combining marks, halfwidth katakana [[16]](https://mitchellh.com/writing/grapheme-clusters-in-terminals). Each asserts the expected width via `grapheme_widths()` AND asserts the projection writes the correct number of cells (via `TestBackend` buffer inspection). **Cell-diff corruption from width drift is the failure mode the test catches.**
- Failing test: each corpus class asserts its expected width; a ratatui upgrade that changes cell assignment is caught.
- Mode 2027 query deferred to Step 8 (needs real crossterm event stream; Step 4 uses runefix-core's default terminal policy, emoji=2/CJK=2).
- **Pi equivalent**: pi has a grapheme-aware width engine: `graphemeWidth()` in `packages/tui/src/utils.ts` [L167](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/utils.ts#L167), using `Intl.Segmenter` (grapheme segmentation) + custom emoji/CJK/zero-width width (emoji=2, CJK=2). pi-rs's `GraphemeWidth` trait + runefix-core impl is the Rust-native equivalent. The P13 corpus is pi-rs's regression spec (pi has no corpus). Cite with line anchors per §9.5.

### Step 5 — Streaming markdown pipeline

- pulldown-cmark re-parse per coalesced frame (ADR 0010, ADR 0033) [[23]](https://github.com/pulldown-cmark/pulldown-cmark). tree-sitter highlight on code blocks via `tree-sitter-highlight` [[13]](https://docs.rs/tree-sitter-highlight/latest/tree_sitter_highlight/) (tree-sitter is error-tolerant, ADR 0010 [[24]](https://github.com/tree-sitter/tree-sitter)). **Block-granular cache** (ADR 0033): finalized code blocks cached as highlighted lines (keyed by code content + lang + width + theme), only the tail block is re-highlighted each frame. The cache lives in the new `markdown.rs` module, separate from `RenderState`'s message cache (ADR 0031).
- **"Incremental" = re-highlight tail block only** (ADR 0033): tree-sitter-highlight's `highlight()` takes `&[u8]` and re-parses internally. It does not expose the incremental `old_tree` API. "Incremental" means only the tail block is re-highlighted, not all blocks (block-granular caching), not incremental tree edit within a block.
- **Partial closing fences** (ADR 0033): during streaming, a code block's closing fence arrives char by char. The pipeline trims partial closing fences before parsing (like pi's `trimPartialClosingFences`, markdown.ts L37-L55) to prevent flicker.
- **Grammar set** (ADR 0033, research.md D-B): minimal daily-driver set: rust, TypeScript/JavaScript, bash, json. Behind Cargo features. Languages without a bundled grammar fall back to plain styling (ADR 0010). Expand to Oracle's full set in Phase 4.
- Incomplete-code corpus per grammar (P18: tree-sitter error recovery varies by grammar, "catastrophically bad" recovery in some grammars on mid-typing edits [[17]](https://github.com/tree-sitter/tree-sitter/issues/2404); a grammar with bad recovery falls back to plain styling for the growing tail block).
- Failing test: assert a finalized block is cached (not re-highlighted); assert the tail block re-highlights each frame; assert incomplete code doesn't panic; assert partial closing fences don't cause flicker.
- **Pi equivalent**: pi's `Markdown` component (markdown.ts [L151](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/components/markdown.ts#L151)) + `highlightCode()` using `highlight.js` (theme.ts [L1138](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/coding-agent/src/modes/interactive/theme/theme.ts#L1138)). pi-rs uses tree-sitter-highlight (error-tolerant, ADR 0010 rejected regex-based). pi-rs's block-granular highlight caching is the improvement over pi's per-component caching (P11). Cite with line anchors.

### Step 6 — Theme loader

- Typed `Theme` struct (D-F, ADR 0034) with `ColorValue` enum (Hex, Indexed, Reset). Vars resolved at load time with cycle detection (like pi's resolveThemeColors, theme.ts L310-L322). Read `~/.pi/agent/themes/*.json` (ADR 0020). Unknown keys tolerated (skipped, ADR 0020). Missing required keys default to Reset. `ColorValue` maps to `ratatui::style::Color` (Hex->Rgb, Indexed->Indexed, Reset->Reset).
- Capture-to-palette `match` (ADR 0012, ADR 0034): tree-sitter captures -> pi's 9 `syntax*` keys. Replaces Step 5's hardcoded `capture_to_style`. The mapping is a single `match` expression (ADR 0012: 'single place to tune').
- Live theme switch: `RenderEvent::ThemeChanged` flushes the block cache (ADR 0010) and re-projects.
- Failing test: assert a theme loads and resolves vars; assert live switch restyles the RMM without a full re-parse; assert unknown keys are tolerated; assert missing keys default to Reset.
- **Snapshot testing** (ADR 0034): three layers using insta. (1) Resolved Theme struct per theme file (catches var resolution regressions). (2) Rendered TestBackend buffer per theme with sample markdown + code highlighting (catches capture-to-palette visual regressions). (3) Capture mapping output per tree-sitter capture name (catches mapping table regressions). Direct pi vs pi-rs cross-compare rejected (ANSI vs Color enum, different representations).
- **Pi equivalent**: pi's `theme-schema.json` (the 9 `syntax*` keys, ~50 total color keys) [[20]](https://github.com/earendil-works/pi/blob/v0.82.0/packages/coding-agent/src/modes/interactive/theme/theme-schema.json), `resolveVarRefs` (theme.ts L293-L318), `resolveThemeColors` (theme.ts L310-L322). pi-rs loads themes unchanged (ADR 0012). Vars resolved at load (ADR 0034 corrects research.md D-F: 'resolved at render time' -> 'resolved at load time').

### Step 7 — Keybindings: key parsing + registry + user config

- **Key parsing** (`keys.rs`): port pi's `keys.ts` [[31]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/keys.ts) to Rust. `KeyId` type (modifier+key strings like `"ctrl+c"`, `"shift+enter"`, `"alt+left"`). `parse_key(raw: &[u8]) -> Option<KeyId>`: Kitty keyboard protocol (CSI-u), legacy escape sequences, xterm modifyOtherKeys, shift+enter disambiguation, printable key decoding, non-Latin layout support (base layout key fallback). `matches_key(raw: &[u8], key_id: &str) -> bool`. Kitty protocol state flag (`set_kitty_protocol_active`/`is_kitty_protocol_active`). This is the raw-byte-to-KeyId layer; it does not depend on the agent loop.
- **Keybinding registry** (`keybindings.rs`): port pi's `keybindings.ts` [[32]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/keybindings.ts) + `core/keybindings.ts` [[33]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/coding-agent/src/core/keybindings.ts). ~80 keybinding IDs: ~30 TUI (`tui.editor.*`, `tui.input.*`, `tui.select.*`) + ~50 app (`app.interrupt`, `app.exit`, `app.session.*`, `app.model.*`, etc.). `KeybindingsManager`: definitions (default keys + description), user bindings, conflict detection (same key bound to multiple actions), rebuild on config change, `matches(raw, keybinding_id)`, `get_keys(id)`, `get_conflicts()`, `get_resolved_bindings()`.
- **User config** (`keybindings.rs`): load `~/.pi/agent/keybindings.json` (ADR 0020 shared tree). User config overrides defaults per-key. Legacy name migration (pi's `KEYBINDING_NAME_MIGRATIONS`: `cursorUp` -> `tui.editor.cursorUp`, etc. [[33]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/coding-agent/src/core/keybindings.ts)). Platform-specific defaults (Windows: `app.suspend` unbound, `app.clipboard.pasteImage` = `alt+v`; Darwin: `app.tree.foldOrUp` = `alt+left` first).
- **Expand `InputEvent`** (`input.rs`): replace the single `Quit` variant with a typed enum mirroring pi's keybinding action surface. Phase 2 wires only the render-layer actions (Quit, scroll). Editor/session/model actions are Phase 3 (the enum exists but those variants are stubs or deferred). The `CrosstermInput` (Step 3) is replaced by a `KeybindingInput` that reads raw crossterm events, calls `parse_key`, then `KeybindingsManager::matches` to resolve the action.
- **`/reload` support**: `KeybindingsManager::reload()` re-reads `keybindings.json` (Phase 3 wires the `/reload` command; the method exists now).
- Failing test: assert `parse_key` correctly identifies Kitty CSI-u sequences, legacy escape sequences, modifyOtherKeys sequences, and raw control characters; assert `matches_key` matches user-overridden bindings; assert conflict detection flags double-bound keys; assert legacy name migration produces namespaced IDs; assert unknown keys in user config are tolerated (skipped); assert platform-specific defaults differ on Windows/Darwin.
- **Pi equivalent**: pi's `keys.ts` [[31]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/keys.ts) (key parsing, 1401 lines), `keybindings.ts` [[32]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/tui/src/keybindings.ts) (TUI keybinding registry, 244 lines), `core/keybindings.ts` [[33]](https://github.com/earendil-works/pi/blob/083e61621276bff9f6faefab87ce07fcd98734e2/packages/coding-agent/src/core/keybindings.ts) (app keybindings + config loader + migration, 370 lines). pi-rs ports these as Rust modules with the same KeyId format and keybinding IDs (byte-compatible `keybindings.json`). Cite with line anchors per §9.5.

### Step 8 — Replay wiring + 20MB gate

Real Corpus session from `~/.pi/agent/sessions` for human sign-off if available (ADR 0020 shared tree).
- Failing test: the 20MB replay runs to completion without panic; final-frame snapshots match.
- **No pi equivalent** (pi-replay is a pi-rs-native tool; pi has no equivalent replay harness, ADR 0007). State explicitly per §9.5.

### Step 9 — Benchmarks + CI tmux + screen lanes

- Criterion: frame-time (p99 < 16ms per coalesced frame) and input-latency (p99 < 16ms keystroke-to-frame) under synthetic streaming workloads [[25]](https://docs.rs/criterion). Baselines committed. ## Tracked open item: first-class Core-owned intercom (future ADR)

A first-class, Core-owned session intercom (sessions auto-discover each other and message without FS writes) is a pi-rs-native addition with **no pi equivalent**. The existing implementations are extension-level workarounds:

- `pi-intercom` [[26]](https://github.com/nicobailon/pi-intercom/blob/5caa4aa1/README.md): a separate extension that spawns a standalone TypeScript broker process. Sessions connect over a Unix socket (named pipe on Windows) with a length-prefixed JSON protocol. The broker routes 1:1 messages by session ID. `ask` blocks up to 10 min. Messages persist to Pi session history (FS). Config at `~/.pi/agent/intercom/config.json`.
- `pi-subagents` native supervisor channel [[27]](https://github.com/nicobailon/pi-subagents/blob/main/README.md) (no `pi-intercom` needed): `contact_supervisor` (child to parent, `need_decision`/`interview_request`/`progress_update`) and `subagent_supervisor({ action: "reply" })` (parent to child), scoped to the exact spawning session via `PI_SUBAGENT_PARENT_SESSION`. Exposes `intercom` as a fallback name if no external tool owns it.

Both of these documented implementations are extension-level; neither has Core support. In `pi-subagents`, `pi.events` is in-process only and explicitly "does not reach separate Pi processes or child subagents" [[27]](https://github.com/nicobailon/pi-subagents/blob/main/README.md). In `pi-intercom`, cross-process coordination requires the standalone broker process or the FS [[26]](https://github.com/nicobailon/pi-intercom/blob/5caa4aa1/README.md). No documented pi implementation provides Core-owned, in-process session messaging without FS writes.

The owner's intent: make this a first-class citizen. The Core runtime maintains a session registry (live sessions by ID) and an in-process message bus (tokio mpsc/broadcast). Sessions register on start and message without FS writes. Subagents spawned as headless children register back over their stdio/UDS. This is hard-to-reverse, shapes the Core's concurrency model (GOALS goal 2), and warrants a dedicated ADR + plan before implementation.

**Status:** tracked here so it is not lost. Scoping deferred to a dedicated session (research the broker-vs-Core-registry trade-off, the message-bus topology, the auto-discovery mechanism, and the relationship to ADR 0018's "Core is designed subagent-aware"). Not a Phase 2 blocker; the render thread and RMM do not depend on it.
