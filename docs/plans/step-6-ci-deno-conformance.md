# Step 6 plan: CI Deno lane + protocol conformance tests

The last Phase 1 deliverable. A CI Deno lane that runs the codec tests and a protocol conformance test that reads `host/protocol/fixtures.bin` (generated by Rust, ADR 0022 Q10), decodes each frame, asserts the shape matches the generated TS types, re-encodes, and the Rust side asserts byte-identity.

## Scope

1. A Deno conformance test (`host/conformance_test.ts`) that reads `host/protocol/fixtures.bin`, decodes each length-prefixed msgpack frame, asserts the decoded shape matches the expected TS type, re-encodes, and writes the re-encoded bytes for the Rust side to compare.
2. A CI job (`.github/workflows/ci.yml`) that installs Deno, runs `deno test host/codec_test.ts` and `deno test host/conformance_test.ts` on every PR.
3. The exit gate 1 proof: "typed protocol round-trip: Core to host and back, demo runnable from CI" — the conformance test IS the demo, running in CI.

## TDD order

1. Write the conformance test (RED: no test. GREEN: reads fixtures.bin, decodes, asserts shapes, re-encodes).
2. Add the CI Deno job.
3. Verify the round-trip is byte-identical (Rust generates, Deno decodes + re-encodes, bytes match).

## Oracle citations

The Host Protocol is pi-rs-native (pi is single-process). No Oracle permalink. ADR 0022 Q10 is the design source for the fixtures mechanism.

## Out of scope

- The real host binary's Deno tests (step 5's `host/main.ts` compiles but its end-to-end test against the supervisor is a Rust integration test, not a Deno test).
- Running the codec benchmark in CI (it's a one-shot decision tool, not a gate).
